# SILVER — 대전 어르신 맞춤 복지 찾기

대전광역시의 노인복지 사업 25개를, 어르신이 **스스로** 찾아보고 챙길 수 있도록 만든 웹 서비스입니다.
2026 정보과학 프로젝트 · 대전과학고등학교 2204 최세민

🔗 **<https://silver-lilac.vercel.app/>**

---

## 무엇을 해결하려고 만들었나

복지 안내문은 어르신이 읽기 어렵게 쓰여 있습니다. 자격 요건이 행정 용어로 적혀 있어
**내가 받을 수 있는지조차 알기 어렵고**, 대부분의 복지는 신청해야만 받을 수 있는데
그 사실을 모르고 지나치는 경우가 많습니다.

이 서비스는 세 가지로 접근합니다.

1. **물어보고 판정해 줍니다** — 어르신이 자격 요건을 해석할 필요가 없습니다.
2. **쉬운 말을 먼저 보여줍니다** — 행정 문서 원문은 원할 때만 펼쳐 봅니다.
3. **기억해 둡니다** — 관심 있는 복지와 신청 현황을 계정에 저장합니다.

## 기능

### 메인 기능 — 내 맞춤 복지 찾기

8단계 설문(연세·사는 곳·가구·소득·건강 등)에 답하면, 25개 사업을 하나씩 따져
**받으실 수 있어요 / 확인이 필요해요 / 해당되지 않아요** 로 나누고 *왜 그런지* 이유를 함께 보여줍니다.

- 모든 질문에 **"잘 모르겠어요"** 를 고를 수 있고, 그래도 결과가 나옵니다
  (모르는 항목은 단정하지 않고 "확인이 필요해요" 로 보냅니다)
- 판정 기준은 `STD` 상수에 모아 두었습니다. 기초연금 선정기준액, 기준 중위소득 등
  해마다 바뀌는 값은 **이 한 곳만 고치면** 전체 판정에 반영됩니다

### 서브 기능

| # | 기능 | 설명 |
|---|---|---|
| 1 | **복지 모두 보기** | 8개 분야 필터 · 신청 가능만 보기 · 카드를 누르면 상세 |
| 2 | **단계식 읽기** | 상세는 **쉬운 말이 기본**. 칸을 누르면 그 자리에 원래 안내가 펼쳐집니다 |
| 3 | **복지 정보 보기** | 상황별 길잡이 8 · 쉬운말 사전 36 · 자주 묻는 질문 15 · 전화번호부 12 · 신청일정 달력 18 · 서류 안내 8 |
| 4 | **어려운 말 자동 밑줄** | 본문을 훑어 36개 용어를 찾아 밑줄 치고, 누르면 뜻풀이가 뜹니다 |
| 5 | **회원가입 / 로그인** | Supabase Auth (이메일·비밀번호, 이메일 인증) |
| 6 | **즐겨찾기 저장** | 별표한 복지를 DB 에 저장, 다시 오면 그대로 (`favorites`) |
| 7 | **내 기록 저장** | 이미 받고 있어요 / 신청했어요 (`welfare_status`) |
| 8 | **내 정보 저장·불러오기** | 설문 답을 저장해 두고, 다음에 설문 없이 바로 결과 (`profile_info`) |
| 9 | **마이페이지** | 별표·이미 받는 복지·신청한 복지를 한 화면에 모아 보기 |

## 파일 구성

빌드 과정이 없는 **정적 사이트**입니다. 번들러도 패키지 매니저도 쓰지 않습니다.

| 파일 | 역할 |
|---|---|
| `index.html` | 화면 전체 · 복지 데이터 25건 · 판정 엔진 · 마이페이지 |
| `config.js` | Supabase 주소와 공개 키 |
| `supabaseClient.js` | 데이터베이스 연결 |
| `supabaseFeatures.js` | 로그인 · 즐겨찾기 · 내 기록 |
| `profileFeature.js` | 설문 답 저장·불러오기 |
| `내정보저장_권한.sql` | `profile_info` 테이블과 보안 정책 |

### 불러오는 순서가 중요합니다

`supabaseFeatures.js` 와 `profileFeature.js` 는 `index.html` 안의 함수
(`toggleFav` · `openModal` · `showResult`)를 **가로채서** 기능을 덧붙입니다.
그래서 반드시 이 순서로 불러와야 합니다.

```
supabase-js (CDN) → config.js → supabaseClient.js → index.html 본문 → supabaseFeatures.js → profileFeature.js
```

로그인 기능 파일이 없어도 **앱 자체는 그대로 동작합니다**(저장만 되지 않습니다).
마이페이지도 로그인 파일이 있는지 확인한 뒤 읽어 가도록 되어 있습니다.

## 로컬에서 실행하기

`file://` 로 직접 열면 로그인이 동작하지 않습니다. 반드시 웹서버로 띄우세요.

```bash
python -m http.server 8000
```

그 다음 <http://127.0.0.1:8000> 으로 접속합니다.
VS Code 를 쓰신다면 Live Server 확장의 `Go Live` 도 같습니다.

## 데이터베이스

Supabase(PostgreSQL)를 씁니다. 세 개의 테이블을 사용합니다.

| 테이블 | 담는 것 | 키 |
|---|---|---|
| `favorites` | 별표한 복지 | `(user_id, welfare_id)` |
| `welfare_status` | 복지별 상태 (`received` / `applied`) | `(user_id, welfare_id)` |
| `profile_info` | 설문 답 한 벌 (JSONB) | `user_id` |

### 보안

세 테이블 모두 **RLS(행 수준 보안)** 가 켜져 있고, 다음 정책이 걸려 있습니다.

```sql
using (auth.uid() = user_id) with check (auth.uid() = user_id)
```

로그인한 사람은 **자기 행만** 읽고 쓸 수 있습니다. 로그인하지 않은 상태(`anon`)에서는
세 테이블 모두 권한이 회수되어 있어 접근하면 `42501` 이 떨어집니다.

> `config.js` 의 키는 **publishable key** 로, 브라우저에 공개되는 것을 전제로 설계된 키입니다.
> 실제 데이터 보호는 위의 RLS 정책이 담당합니다. 비밀번호나 service role key 는
> 이 저장소에 들어 있지 않습니다 (`.gitignore` 로 막아 두었습니다).

## 배포

Vercel 정적 배포입니다. `main` 에 push 하면 자동으로 반영됩니다.

배포 주소가 바뀌면 Supabase 대시보드의
**Authentication → URL Configuration** 에서 `Site URL` 과 `Redirect URLs` 를
새 주소로 갱신해야 이메일 인증 링크가 정상 동작합니다.

### 이메일 인증에 관한 메모

회원가입에 이메일 인증을 걸어 두었습니다. 개인 정보를 다루는 서비스이므로,
그 주소가 실제 본인의 것인지 확인하기 위해서입니다.

다만 Supabase **내장 메일 발송기**는 조직 팀 구성원 주소로만 보낼 수 있고
프로젝트 전체 시간당 2통 제한이 있습니다. 아무에게나 인증 메일이 가게 하려면
**커스텀 SMTP** 를 등록해야 합니다 (Authentication → Emails → SMTP Settings).

메일이 오지 않는 경우를 대비해 로그인 창에 **`인증 메일 다시 보내기`** 버튼을 두었고,
발송 한도 초과·주소 미허용 오류는 한국말 안내로 바꿔서 보여줍니다.

> 참고로 **개인별 맞춤은 이메일 인증이 아니라** 계정이 만들어질 때 발급되는
> `auth.uid()` 와 위의 RLS 정책이 담당합니다. 이메일 인증은 계정을 실제 본인 주소에
> 묶어 두는 **개인정보 보호** 장치입니다.
