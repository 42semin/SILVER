# SILVER — 대전 어르신 맞춤 복지 찾기

대전광역시의 노인복지 사업 25개를, 어르신이 **스스로** 찾아보고 챙길 수 있도록 만든 웹 서비스입니다.
2026 정보과학 프로젝트 · 대전과학고등학교 2204 최세민

🔗 **<https://silver-lilac.vercel.app/>**

---

## 무엇을 해결하려고 만들었나

복지 안내문은 어르신이 읽기 어렵게 쓰여 있습니다. 자격 요건이 행정 용어로 적혀 있어
**내가 받을 수 있는지조차 알기 어렵고**, 대부분의 복지는 신청해야만 받을 수 있는데
그 사실을 모르고 지나치는 경우가 많습니다.

이 서비스는 세 가지로 접근합니다.

1. **물어보고 판정해 줍니다** — 어르신이 자격 요건을 해석할 필요가 없습니다.
2. **쉬운 말을 먼저 보여줍니다** — 행정 문서 원문은 원할 때만 펼쳐 봅니다.
3. **기억해 둡니다** — 관심 있는 복지와 신청 현황을 계정에 저장합니다.

## 기능

### 메인 기능 — 내 맞춤 복지 찾기

8단계 설문(연세·사는 곳·가구·소득·건강 등)에 답하면, 25개 사업을 하나씩 따져
**받으실 수 있어요 / 확인이 필요해요 / 해당되지 않아요** 로 나누고 *왜 그런지* 이유를 함께 보여줍니다.

- 모든 질문에 **"잘 모르겠어요"** 를 고를 수 있고, 그래도 결과가 나옵니다
  (모르는 항목은 단정하지 않고 "확인이 필요해요" 로 보냅니다)
- 판정 기준은 `STD` 상수에 모아 두었습니다. 기초연금 선정기준액, 기준 중위소득 등
  해마다 바뀌는 값은 **이 한 곳만 고치면** 전체 판정에 반영됩니다

### 회원과 비회원의 차이

| | 비회원 | 회원 |
|---|---|---|
| 설문·결과·별표·내 기록 | ✅ 이 브라우저에만 저장 | ✅ 어느 기기에서나 (Supabase) |
| 결과 링크 만들기 · 링크로 보기 | ✅ | ✅ |
| 내 휴대전화 문자 앱으로 보내기 | ✅ (서버가 번호를 받지 않음) | ✅ |
| 등록한 번호로 서버가 문자 발송 | ❌ | ✅ 나·가족에게 |
| 가족 그룹 | ❌ | ✅ |

비회원에게서 **1회용으로 전화번호를 받아 서버가 문자를 보내는 기능은 두지 않았습니다.**
로그인하지 않은 누구나 아무 번호로나 문자를 보내게 되면 ① 남의 번호로 스팸을 보내는 데 악용될 수 있고,
② 발송 요금이 그대로 새며, ③ 본인 번호인지 확인할 길이 없습니다. 대신 비회원은
`sms:` 링크로 **자기 휴대전화의 문자 앱**이 열려 직접 보내게 했습니다. 서버는 번호를 아예 받지 않습니다.

### 5회차에서 동료 피드백을 반영한 것 (2026-11-18)

4회차 발표 뒤 받은 피드백 가운데, 코드 한 곳만 고쳐 해결되는 9건을 반영했습니다.
자세한 계획은 [`피드백_구현계획.md`](피드백_구현계획.md) 에 있습니다.

- **글자 크기 버튼** — 화면 맨 위 3단계 버튼 (`zoom` + `localStorage`)
- **전화번호 모음에 112 추가** — 119 와 함께 맨 위 긴급 칸에 배치
- **비회원 맞춤 복지 검사 / 메일 인증 없이 쓰기** — 로그인하지 않아도 별표·내 기록·내 정보가
  이 기기에 저장됩니다. 가로막던 `confirm` 창도 없애고 안내 띠로 바꿨습니다
- **“혼자 지내고 계신가요” 질문 오류** — 가구 상태 세 질문(혼자·손주·부부)이 기본값 `false` 탓에
  **아무것도 고르지 않아도 ‘아니오’가 눌린 것처럼 보이고, 셋 다 ‘예’로 고르는 모순된 답이 가능**했습니다.
  하나만 고르는 질문(`B.living`)으로 합치고, 고르지 않으셨으면 단정하지 않고
  “확인이 필요해요”로 보냅니다
- **선택 칸만 다시 입력하기** — 결과 화면의 “✏ 고칠 칸만 눌러 주세요”
- **쉬운 단어** — ‘가구원’→‘한집에 사시는 분’, ‘소득’→‘집에 들어오는 돈’ 등으로 고치고
  어려운 질문마다 쉬운 말 설명을 달았습니다
- **65세 미만 부적격 알림** — 나이를 적는 즉시 알려 드려, 8단계를 다 채우고 나서
  “해당 없음”을 보는 일이 없게 했습니다
- **신청 기간·마감일** — 신청일정 달력을 복지 번호로 묶어 상세 화면에 📅 칸을 만들고,
  오늘 날짜와 견주어 “이번 달입니다 / 약 N일 남았습니다 / 올해 일정은 지났습니다”를 보여 줍니다

### 6회차에서 반영한 화면 피드백 (2026-11-18)

“글이 너무 많고 스크롤이 길다”는 지적을 중심으로 **읽는 양을 줄이고, 신청으로 바로 이어지게** 고쳤습니다.

- **결과를 인덱스로** — ‘받으실 수 있어요’를 카드 대신 **아이콘 + 제목만 있는 작은 칸**으로 바꾸고
  **한 행에 세 개**씩 놓았습니다. 누르면 지금까지와 같은 상세 팝업이 뜨고,
  **왜 받으실 수 있는지(판정 이유)는 그 팝업 맨 위**에서 보여 드립니다
- **‘수정하기’ 화면** — ‘고칠 칸만 눌러 주세요’ 칩 여덟 개 대신 **✏️ 수정하기** 버튼 하나를 두고,
  누르면 **실제로 입력된 답을 ‹ › 화살표로 한 칸씩 넘겨 보는 확인 화면**이 열립니다.
  고칠 것이 보이면 그 칸만 다시 답하고 **확인 화면 그 자리로** 돌아옵니다 (키보드 ←/→ 도 됩니다)
- **실제로 이어 주기** — 상세 팝업 맨 아래 **🔗 바로 이어 드립니다** 칸을 만들어
  **☎ 전화 걸기(`tel:`)·🌐 공식 홈페이지·📍 지도 검색**을 버튼으로 뽑았습니다.
  지도와 치매안심센터 번호는 **설문에서 고르신 구(區)** 로 맞춰 드립니다
  (홈페이지 주소는 2026-11-18 에 직접 열어 확인한 공식 누리집만 넣었고, 전화번호는 원자료의 ‘문의’ 칸만 씁니다)
- **어려운 말 풀이** — 36개를 뜻까지 다 펼쳐 놓지 않고 **단어만 작은 토큰**으로 보여 주다가,
  누른 단어 하나만 뜻·예시·관련 복지 링크를 펼칩니다
- **자질구레한 회색 글씨 삭제** — 상세 팝업의 ‘쉬운 말로 먼저 알려드립니다…’, ‘더 궁금하면…’과
  결과 맨 아래 ‘이 결과는 참고 자료입니다…’ 문단을 지웠습니다
  (같은 내용은 화면 아래 출처 줄에 이미 적혀 있습니다)

### 최종본에서 반영한 피드백 — 음성 안내와 배경음악 (2026-11-27)

난이도가 높아 뒤로 미뤄 두었던 두 건을 구현했습니다. 둘 다 **브라우저에 이미 들어 있는 표준 기능**만
쓰므로, 받을 음원도 없고 서버로 나가는 자료도 없습니다. 코드는 `index.html` 맨 아래
`window.Voice` · `window.BGM` 두 덩어리에 모여 있습니다.

- **질문을 읽어주는 음성 안내 (`###`)** — 설문의 질문 글 **바로 옆에 작은 스피커(🔊)** 를 붙였습니다.
  누르면 `질문 → 쉬운 말 설명 → 답 버튼`을 **한 칸씩 차례로** 읽고, 읽는 동안 그 답 버튼에
  **불이 한 번 켜졌다 꺼집니다**(지금 어디를 읽는지 눈으로도 따라올 수 있게).
  화면 제목 옆 **“🔊 모두 읽기”** 는 그 화면 전체를 이어서 읽습니다.
  읽는 중인 스피커를 다시 누르면 그치고, 답을 고르거나 다음 칸으로 넘어가도 저절로 멈춥니다.
  **Web Speech API**(`speechSynthesis`)를 쓰며, 한국어 목소리를 골라 어르신께 맞춰
  조금 느리게(`rate 0.88`) 읽습니다. 음성을 지원하지 않는 브라우저에서는 스피커를 아예 감춥니다
  (윈도우 크롬·엣지는 `Microsoft Heami — ko-KR` 로 읽힙니다).
- **“임영웅 노래” (`##`) → 저작권 없는 자체 연주** — 가요 음원은 저작권이 있어 사이트에 올릴 수 없습니다.
  그래서 피드백의 본뜻(“어르신이 머물고 싶은 화면”)만 살려, **느린 5음계(라단조 펜타토닉) 연주를
  Web Audio API 로 그 자리에서 만들어** 아주 작게(`0.085`) 들려드립니다. 글자 크기 단추 옆 **♪** 로
  켜고 끄며, 켠 상태는 이 기기에 기억됩니다(브라우저가 소리를 막으므로 다시 오시면 화면을 처음
  누르시는 순간 이어서 틉니다). **음성 안내가 나오면 음악이 저절로 작아져**(0.085 → 0.019)
  말소리를 가리지 않습니다.

### 길찾기 — 집에서 신청처까지 (2026-11-27)

“전화번호와 홈페이지는 좋은데, 정작 **어디로 가야 하는지**는 모르겠다”는 지적을 반영했습니다.
그동안 📍 단추는 `서구 행정복지센터` 처럼 **구 단위로 뭉뚱그려** 지도 검색을 열었습니다.
어르신이 사시는 동의 주민센터가 어디인지는 여전히 직접 찾으셔야 했습니다.

- **동 단위로 정확하게** — 대전광역시 공공데이터 「행정복지센터 현황」(2021-12-31) 의
  **81곳 주소를 `CENTER` 상수에 넣고**, 설문에서 고르신 동의 센터를 이름과 주소로 집어 드립니다.
  (예: `서구 행정복지센터` → **둔산1동 행정복지센터 · 대전광역시 서구 둔산중로 65**)
- **🚶 집에서 가는 길** — 고르신 동에서 그 센터까지 **버스·지하철 경로**를 엽니다.
  구글 지도 길찾기 URL 은 **한글 주소 글자만으로** 경로를 찾아 주므로 좌표를 미리 구해 둘 필요도,
  API 키를 발급받아 코드에 넣을 필요도 없습니다 (`travelmode=transit`).
- **주소가 확인된 곳에만 겁니다** — 기관 이름만 아는 곳(경로당·치매안심센터 등)은
  엉뚱한 곳으로 안내할 수 있어 **길찾기를 달지 않고 지도 검색만** 남겼습니다. `ISADDR` 이 이것을 가립니다.
  서구 도안동은 2021년 자료에 없어 길찾기가 뜨지 않습니다.
- **아직 동을 고르지 않으셨으면** 📍 아래에 “설문에서 동을 고르시면 우리 동 센터까지
  가는 길을 알려 드립니다” 라고 알려 드립니다.

> 이 작업을 하다가 **설문의 동 목록에서 세 곳이 빠져 있던 것**을 찾아 함께 고쳤습니다 —
> 서구 **만년동**, 대덕구 **법1동·법2동**. 그동안 이 세 동에 사시는 분은 자기 동을 고르실 수 없었습니다.

### 불러오는 순서가 중요합니다

`supabaseFeatures.js` · `profileFeature.js` · `familyShareFeature.js` 는 `index.html` 안의 함수
(`toggleFav` · `openModal` · `showResult` · `renderMyPage`)를 **가로채서** 기능을 덧붙입니다.
그래서 반드시 이 순서로 불러와야 합니다.

```
supabase-js (CDN) → config.js → supabaseClient.js → index.html 본문
  → supabaseFeatures.js → profileFeature.js → familyShareFeature.js
```

로그인 기능 파일이 없어도 **앱 자체는 그대로 동작합니다**(저장만 되지 않습니다).
마이페이지도 로그인 파일이 있는지 확인한 뒤 읽어 가도록 되어 있습니다.

## 데이터베이스

Supabase(PostgreSQL)를 씁니다. 세 개의 테이블을 사용합니다.

| 테이블 | 담는 것 | 키 |
|---|---|---|
| `favorites` | 별표한 복지 | `(user_id, welfare_id)` |
| `welfare_status` | 복지별 상태 (`received` / `applied`) | `(user_id, welfare_id)` |
| `profile_info` | 설문 답 한 벌 (JSONB) | `user_id` |

### 보안

세 테이블 모두 **RLS(행 수준 보안)** 가 켜져 있고, 다음 정책이 걸려 있습니다.

```sql
using (auth.uid() = user_id) with check (auth.uid() = user_id)
```

로그인한 사람은 **자기 행만** 읽고 쓸 수 있습니다. 로그인하지 않은 상태(`anon`)에서는
세 테이블 모두 권한이 회수되어 있어 접근하면 `42501` 이 떨어집니다.

> `config.js` 의 키는 **publishable key** 로, 브라우저에 공개되는 것을 전제로 설계된 키입니다.
> 실제 데이터 보호는 위의 RLS 정책이 담당합니다. 비밀번호나 service role key 는
> 이 저장소에 들어 있지 않습니다 (`.gitignore` 로 막아 두었습니다).

### 가족 그룹 · 공유 링크 (`가족공유_문자.sql`)

| 테이블 | 담는 것 | 브라우저에서 |
|---|---|---|
| `member_profile` | 아이디(영문 소문자·숫자 4~20자)·가족에게 보일 이름 | 내 행만 쓰기, 가족 행 읽기 |
| `family_groups` · `family_members` | 그룹과 구성원 (`owner` / `member`) | 읽기만 — 바꾸는 일은 RPC 로만 |
| `family_requests` | 아이디로 보낸 가족 요청 (받는 분이 수락해야 들어옴) | 읽기만 |
| `family_invites` | 초대 링크 토큰 (3일, 5명) | 읽기만 |
| `shared_results` | 공유한 설문 답 + 만료일 | 내가 만든 것만 읽기 |
| `member_phones` · `phone_verifications` · `sms_log` | 전화번호 **암호문**, 인증번호 해시, 발송 기록 | **접근 불가** (Edge Function 전용) |

- 가족이 되면 `profile_info` · `favorites` · `welfare_status` 에 **읽기 전용** 정책 `가족은 읽기` 가 더해집니다.
  남의 정보를 고치는 것은 여전히 막혀 있습니다.
- 그래서 내 자료를 불러올 때는 반드시 `.eq("user_id", 내 id)` 로 거릅니다 (`supabaseFeatures.js` 를 그렇게 고쳤습니다).
- 링크 토큰은 `pgcrypto` 의 `gen_random_bytes(16)` — 추측할 수 없는 128비트 난수입니다.
- 공유 링크는 **로그인 없이** 열리므로, 링크를 가진 사람은 누구나 그 결과(나이·소득·건강 답)를 봅니다.
  그래서 기한이 지나면 저절로 닫히고, 만든 사람이 언제든 지울 수 있게 했습니다
  (비회원은 링크를 만들 때 받은 지우기 열쇠를 이 기기에 보관합니다).

### 전화번호 암호화와 키 관리

전화번호는 데이터베이스에 **평문으로 들어가지 않습니다.**

```
브라우저 ──(HTTPS, 등록할 때 한 번)──▶ Edge Function 'sms'
                                       │ AES-256-GCM 암호화 (Web Crypto API)
                                       │ AAD = user_id  → 암호문을 남의 행에 옮겨 붙이면 풀리지 않음
                                       ▼
                         member_phones.phone_enc = "k1.<IV>.<암호문+인증태그>"
                         member_phones.phone_hash = HMAC-SHA256(별도 키)   ← 발송 횟수 제한용
                         member_phones.last4 = "5678"                        ← 화면 표시용
```

- **알고리즘은 직접 만들지 않았습니다.** 암호화·해시·난수는 모두 Deno 런타임의 표준 Web Crypto API
  (`crypto.subtle` AES-GCM / HMAC-SHA-256, `crypto.getRandomValues`), base64 는 Deno 표준 라이브러리를 씁니다.
- **키는 DB 와 분리되어 있습니다.** 키는 Supabase **Edge Function Secrets** 에만 있고, 코드·저장소·DB 어디에도 없습니다.
  DB 가 통째로 새어 나가도 키 없이는 번호를 읽을 수 없습니다.
- 암호화 키와 HMAC 키는 **서로 다른 키**입니다.
- **키 교체(회전)**: `PHONE_ENC_KEYS` 에 새 키(`k2`)를 더하고 `PHONE_ENC_ACTIVE_KID=k2` 로 바꾸면,
  새 번호는 `k2` 로 암호화되고, 옛 `k1` 암호문은 다음 발송 때 `k2` 로 다시 암호화됩니다.
  모두 바뀐 뒤 `k1` 을 지웁니다.
- 브라우저로는 **끝 4자리**만 돌려줍니다. 평문은 Edge Function 메모리 안에서 문자를 보내는 순간에만 쓰입니다.
- 번호 등록 때 **인증번호(6자리, 5분, 5번까지)** 로 본인 번호인지 확인합니다. 인증번호도 HMAC 해시로만 보관합니다.
- 발송 한도: 인증번호 10분 3회 · 번호당 하루 5회, 공유 문자 회원당 하루 20통 · 번호당 하루 10통.
- 가족에게 보내는 문자는 **같은 가족 그룹**이고 받는 분이 **‘가족 문자 받기’를 켜 둔 경우**에만 갑니다.
- 문자에는 결과 내용 없이 **링크만** 들어갑니다.

> 이메일 주소는 Supabase Auth 가 관리합니다 (Supabase 는 저장 데이터를 디스크 단에서 암호화합니다).
> 전화번호는 그보다 한 단계 더, **애플리케이션 단에서 별도 키로** 암호화한 것입니다.

#### 배포 순서

1. **SQL** — 대시보드 → SQL Editor 에서 `가족공유_문자.sql` 실행
2. **키 만들기** — OS 표준 도구로 32바이트 난수를 만듭니다 (키는 어디에도 적어 두지 마세요)
   ```bash
   openssl rand -base64 32      # 암호화 키
   openssl rand -base64 32      # HMAC 키 (반드시 다른 값)
   ```
3. **비밀값 넣기** — Supabase CLI 로 (또는 대시보드 → Edge Functions → Secrets)
   ```bash
   supabase secrets set PHONE_ENC_KEYS='{"k1":"<암호화 키>"}' PHONE_ENC_ACTIVE_KID=k1 PHONE_HMAC_KEY='<HMAC 키>'
   supabase secrets set SITE_URL=https://silver-lilac.vercel.app ALLOWED_ORIGINS=https://silver-lilac.vercel.app
   # 실제 문자 발송 (없으면 console 모드: 보내지 않고 함수 로그에만 남김)
   supabase secrets set SMS_PROVIDER=solapi SOLAPI_API_KEY=... SOLAPI_API_SECRET=... SMS_SENDER=<사전등록한 발신번호>
   ```
4. **함수 배포** — `supabase functions deploy sms`

국내 문자 발송은 **발신번호 사전등록**이 법으로 필요합니다. 솔라피 콘솔에서 발신번호를 등록한 뒤 `SMS_SENDER` 에 넣으세요.
`SMS_PROVIDER` 를 넣지 않으면 `console` 모드로, 인증번호와 문자 내용이 **Edge Function 로그**에만 찍힙니다(시연용).

## 배포

Vercel 정적 배포입니다. `main` 에 push 하면 자동으로 반영됩니다.

배포 주소가 바뀌면 Supabase 대시보드의
**Authentication → URL Configuration** 에서 `Site URL` 과 `Redirect URLs` 를
새 주소로 갱신해야 이메일 인증 링크가 정상 동작합니다.

### 이메일 인증에 관한 메모

회원가입에 이메일 인증을 걸어 두었습니다. 개인 정보를 다루는 서비스이므로,
그 주소가 실제 본인의 것인지 확인하기 위해서입니다.

다만 Supabase **내장 메일 발송기**는 조직 팀 구성원 주소로만 보낼 수 있고
프로젝트 전체 시간당 2통 제한이 있습니다. 아무에게나 인증 메일이 가게 하려면
**커스텀 SMTP** 를 등록해야 합니다 (Authentication → Emails → SMTP Settings).

메일이 오지 않는 경우를 대비해 로그인 창에 **`인증 메일 다시 보내기`** 버튼을 두었고,
발송 한도 초과·주소 미허용 오류는 한국말 안내로 바꿔서 보여줍니다.

> 참고로 **개인별 맞춤은 이메일 인증이 아니라** 계정이 만들어질 때 발급되는
> `auth.uid()` 와 위의 RLS 정책이 담당합니다. 이메일 인증은 계정을 실제 본인 주소에
> 묶어 두는 **개인정보 보호** 장치입니다.
